项目背景：

我想开发一个 Windows + Android 的低延迟副屏系统，即通过 USB 数据线连接电脑和 Android 手机，让手机作为电脑的第二显示设备使用。

在设计方案前，需要理解目前已有方案的技术区别：

1. spacedesk 类方案：

spacedesk 的核心思路是通过软件方式创建一个虚拟显示器。

Windows 端安装虚拟显示驱动后，系统会认为连接了一块新的显示器。用户可以将窗口拖动到这个虚拟屏幕上。

但是后续显示数据传输采用的是软件显示传输方式：

Windows 生成虚拟屏幕内容 → 捕获显示内容 → 编码压缩 → 通过网络/USB等方式传输 → Android端解码显示。

这种方案的优势：
- 实现相对容易
- 兼容性较好
- 可以实现真正的扩展桌面

不足：
- 显示链路中存在捕获、编码、传输、解码等多个环节
- 延迟较高
- 快速移动窗口或操作时可能出现拖影、卡顿
- 更偏向远程显示，而不是高性能显示设备


2. SuperDisplay 类方案：

SuperDisplay 的目标也是让 Android 设备成为 Windows 的第二块显示器。

它同样需要让 Windows 识别 Android 设备为一个显示设备，但是重点在于优化显示数据路径。

大致流程：

Windows 虚拟显示驱动 → 生成第二显示器画面 → 高效传输显示数据 → Android端直接显示。

相比普通远程桌面方式，它减少了中间的软件截图和处理环节，更接近真实外接显示器的工作方式。

特点：
- Windows真正拥有第二个显示输出
- 可以实现扩展桌面
- USB连接体验较好
- 延迟明显低于普通远程显示方案

难点：
- 涉及Windows显示驱动
- 需要处理显示设备、图形接口、数据传输等底层问题


核心区别：

spacedesk 更像：
“创建一个虚拟显示器，然后把这个显示器的画面通过软件方式传输给手机。”

SuperDisplay 更像：
“让手机尽可能模拟一个真实连接到电脑的显示器，并优化显示数据传输路径。”

目标：
希望设计一个方案，实现 USB 有线连接、低延迟、Android作为电脑扩展屏的效果。
请根据以上背景，自主分析技术路线、架构设计、开发难点和实现方案。
