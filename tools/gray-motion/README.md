# 120 格拍照测试

双击 `D:/S+Zn/Coding/WireView/release/WireView-灰块测试.exe`，无需额外文件或命令行。

先连接正常 WireView 扩展屏，再关闭 120 帧视频的播放器。程序优先在 Parsec 虚拟副屏全屏打开；没有虚拟副屏时使用其他副屏，再没有则在主屏打开。

- 12 列×10 行，共 120 格；从左至右、从上至下，每帧只亮一格，上一格熄灭，最后回到第一格。目标每秒扫完一圈；实际送达较慢时不伪造补亮。
- 每格有较明显的灰色边框；当前 2560×1600 下宽 2 像素。拍照时数格子内部的亮块，不数永久显示的边框。
- 左上角“上一屏／下一屏”按钮切换显示器，“下一屏”同时显示当前序号／总屏数；左右方向键也可循环切屏。切屏只移动测试窗口，不修改显示模式。按钮在网格上方，拍照时不计入亮格。
- F11 切换全屏，空格暂停／继续，Esc 退出。
- 已移除旧版“目标／电脑提交”数字，避免当成平板实显帧率；旧版数字分别是计划出帧率、程序向 Windows 提交画面的次数。

它复用原 `build/spacedesk-latency-probe/motion.cpp` 的 D3D11 灰块绘制方式，不播放视频、不解码视频、不逐帧写日志。静态链接运行库，单个 exe 可独立使用。没有改变 WireView 主机、APK 或投屏设置。

比较时保持相同投屏分辨率、帧率及连接方式。灰块同时减少了播放器解码、编码复杂度和数据量，因此若它更顺，只能先证明视频场景整体负担更大，不能仅据此认定唯一瓶颈是解码或内存。需要证明华为实际帧率时，仍应采集接收端实际呈现记录。

## 手机拍照

手机使用专业／手动拍照，固定手机，用已知曝光时间拍摄；关闭 HDR、夜景等多张合成。推荐先用 1/2 秒：若每秒实际显示约 120、100、90 张新画面，照片中应分别约有 60、50、45 格内部亮过。亮格数量除以曝光秒数，得到该次曝光内的近似平均值；首尾的部分曝光会带来误差。要用 1 秒拍照时，完整 120 格只是一圈，避免更长曝光让多圈叠到同一格上；一张照片不能证明长时间稳定帧率。

这与 [TestUFO 的长曝光检查跳帧方法](https://www.testufo.com/frameskipping) 相同；瞬时截图通常只有一格亮，不能替代手机长曝光。

## 当前闪格版真实验证（2026-11-07）

已增加切屏按钮和方向键。真实点击按钮后，窗口从华为副屏切到主屏、外接屏，再用方向键切回；也验证了反向按钮循环和切屏后 F11 退出／恢复全屏，实际位置及尺寸均正确。最后留在华为副屏（3/3）；华为截图可见两个按钮和持续变化的单格。原始记录 `build/gray-motion/monitor-switch-real-run.json`，截图 `monitor-switch-huawei-a.png`、`monitor-switch-huawei-b.png`。未做新的帧率或鼠标尾延迟测量。

已在原投屏上运行新版，华为两张瞬时截图各只有一个格子内部亮起，位置分别为第 94、80 格。随后按用户要求提亮并加粗边框，再次构建运行，并从华为截图确认边框明显、内部仍只有当前一格亮。当前新版留在副屏；本轮仅确认功能，没有手机光学照片或新的实显帧率结论。

证据：`build/gray-motion/flash-grid-real-run.json`、`flash-grid-huawei-a.png`、`flash-grid-huawei-b.png`、`flash-grid-brighter-huawei.png`。旧移动版 exe 和源码保存在 `build/gray-motion/previous-moving/`。

## 此前移动版验证（历史记录，不作为当前闪格版的性能结论）

通过内置终端构建并打开 exe，未使用 Windows MCP。首次实跑检查了持续移动、全屏、暂停／继续和 Esc 正常退出。当前有两个副屏，已修正默认选择，优先落到正常投屏的 DISPLAY6，窗口客户区 2560×1560，全屏 2560×1600。

华为真机两张截图中，编号从 000972 变为 001095，灰块位置随之改变，确认收到实际新画面。这两张截图仅作功能验证，不用于推算帧率。最终程序在副屏上六次短采样的电脑提交读数为 114.2～120.1 帧/秒；自身私有内存约 36～38 MB、工作集约 54～56 MB，不含单独统计的 GPU 显存。本轮没有证明华为稳定 120 帧，也没有测量鼠标尾延迟。

原始记录与截图：`build/gray-motion/real-run.json`、`real-run-huawei.json`、`huawei-a.png`、`huawei-b.png`。当前测试窗口留在华为扩展屏，供用户自行比较。

构建：在仓库内运行 `powershell -File scripts/build-gray-motion.ps1`。源程序及构建脚本合计不足 300 行，复用现有 `frame_pacer.hpp`。
